# 平台契约

> **这份规范回答四个问题**：aim 是什么、输入是什么、输出是什么、
> 怎么判断它还「通用」。
>
> 规范写成**可替换的规则模板**——**规则**是框架的，**例子**是这个人的。

---

## 一、aim 是什么

**装「人」的仓。**

确认流程（音色定标 → 形象确认 → 人格确认 → 品牌片定稿）的结论，
落成一份 JSON（`models/<slug>/model.json`），再由脚本把它渲染成
**这个人的**素材与片子。

```
   人的确认结论（人写）
          │
          ▼
   models/<slug>/model.json        ← 契约：参数与事实
          │
          ▼
   脚本渲染 → PNG / MP4 / WAV      ← 产物：这个人长什么样、听起来什么样
```

**缝是文件**：下游读 `model.json`（以及它指到的素材），**不 import
本仓的任何模块**。仓里没有跨仓依赖，也没有子模块。

---

## 二、三层：人 = 规则 × 契约 × 产物

**只有 JSON 定义不了一个人。** JSON 是**索引与参数**，不是这个人本身。
人由三层合起来才成立：

| 层 | 在哪 | 管什么 | 换人要不要改 |
| --- | --- | --- | --- |
| **规则** | `specs/` | **框架**：这一类东西该长什么样 | 不用改——代码照着判 |
| **契约** | `models/<slug>/model.json` | **这个人**：参数与事实 | 换人就换这一份 |
| **产物** | `models/<slug>/assets/`（本地） | **这个人**长什么样、听起来什么样：PNG / MP4 / WAV / MP3 | 重新生成 |

**人格在那一段文字里**（`persona`，一整段可读的文字，不是关键词数组）；
**音色在实测特征里**（`voice.measured`：基频、共振峰、语速）；
**形象在渲染出来的像素里**。三样都不在 JSON 的字段值里——
JSON 只是指到它们。

---

## 三、输入

| 输入 | 从哪来 | 缺了会怎样 |
| --- | --- | --- |
| **人的确认结论** | 人写，`scripts/build_model.py` 归一化后落成 `model.json` | 契约坏了 → **报错退出**，不降级 |
| **形象原型参考图** | `model.json` 的 `assets.source`（使用者的素材） | 不跑生成流程，直接用 `assets.mascot` 指的那张 |
| **已生成的素材** | `models/<slug>/assets/` | **降级**（渲染少一块），`doctor` 单独报出来 |
| **内置字体** | 仓内 `assets/fonts/`（入库） | 文字画不出来 → 报错（不画豆腐块） |
| **生成额度** | mcode-tools CLI | 生成类脚本跑不了（测试不碰网络） |
| **ffmpeg / ffprobe** | 系统 | 合成与配音跑不了 |

**空 = 「还没定」，不是错误。** 没定的字段留空，脚本降级或跳过；
**只有契约坏了才是硬错误**（读不了、形状不认识 → 报错退出）。

**契约的每一端各有一份读取器，各认一个 `schema`。**
本仓涨 `schema` 时，**读这份契约的那些端也得跟着涨**——
它们读到「比它认识的旧」就会报错退出，而**报错落在它们那边，
根因在这一头**。所以涨版本号之前先数一遍：**还有谁在读这份契约。**

## 四、输出

| 输出 | 在哪 | 入库？ |
| --- | --- | --- |
| **契约** | `models/<slug>/model.json` | **是** |
| **配乐窗口决策** | `models/<slug>/brand_windows.json` | **是** |
| **内置字体子集 + 出处台账** | `assets/fonts/` | **是** |
| 主形象（白底 / 透明底）、6 姿态表、头像 | `models/<slug>/assets/character/` | 否（使用者的东西） |
| 品牌片姿态素材 | `models/<slug>/assets/brand/assets/` | 否 |
| 品牌片底板与成片 | `models/<slug>/assets/brand/` | 否 |
| 成品音轨（片头 / 片尾混音） | `models/<slug>/assets/brand/audio/` | 否 |
| 配音（音色样音、参照录音） | `models/<slug>/assets/voice/` | 否 |

**入库的是「它在哪」，不是「它本身」。**

**下游怎么用**：读 `model.json`，按它指到的路径取素材，
**不 import 本仓**。相对路径的基准是 `model.json` 所在目录——
下游不需要知道本仓根在哪。

## 五、通用性判据：什么算「绑定了具体的人」

这四条是**可判的**，各有守卫盯着：

| 判据 | 守卫 |
| --- | --- |
| **代码里不许出现这个人的名字、品牌词、配色、定位** | `tests/test_no_hardcoded_person.py`（从模型反推，换了人守卫自动跟着换） |
| **这个人没声明的东西，脚本必须降级或跳过**，不许硬塞默认值 | `tests/test_person_swap.py`（不戴眼镜的人，加眼镜流程整体跳过） |
| **换一个完全不同的人，整套流程必须跑得通** | `tests/test_person_swap.py` |
| **事实的位置是模型，不是代码** | 上面两条一起盯 |

**具体到几条红线**：

- 眼镜规格、衣服色、胸口图标色、铭牌字色、耳麦 → 在 `look_spec` 里；
- 品牌片两张背景的生成 prompt → 在 `brand.backgrounds` 里；
- 品牌片底板的深色 / 浅色 → 在 `brand.colors` 里（**配色也是这个人的事实**：
  写死在渲染脚本里，换个人片子还带着上一个人的颜色）；
- 身份（站名 / 角色 / 定位 / 受众）→ 在 `identity` 里，**没写就空着**，
  **不许拿占位符糊过去**（糊过去了，下游就分不清「定错了」和「还没定」）。

## 六、怎么体检

```bash
python3 scripts/doctor.py            # 体检当前这个人
python3 scripts/doctor.py <model.json>   # 体检指定的人
```

它**只报告，不改**：素材不见了的成因是多样的（没生成 / 路径写错 /
素材在别的机器上），自作主张补一个空文件只会把问题盖住。

退出码：齐了 0，缺东西 1，坏契约 2。
