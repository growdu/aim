# 本地素材回路（`./aim assets build`）

> **这份文档说明什么**：一条命令把「这个人」的全部素材在本地生成出来、
> **留在本地**，供回归测试与功能迭代使用——**不入库**。
>
> 设计定稿于 2026-11-27。

---

## 一、为什么要有它

素材（立绘、姿态表、头像、品牌片、成品音轨）是**使用者自己的**：
版权与口味都是他们的，所以**不入库**——`.gitignore` 挡着
`/models/*/assets/`，位置写在 `models/<slug>/model.json` 的 `assets` 段里。
这是本仓的规矩，不是缺陷。

但规矩带来一个后果：**新克隆的机器上素材一件都没有**。于是 `tests/` 里
那些「素材不在本机」的用例全部 skip——**被测的代码根本没跑**：

| 文件 | CI 上（无素材） |
| --- | --- |
| `tests/test_character_assets.py` | 2 passed / 5 skipped |
| `tests/test_clear_badge.py` | 2 passed / 6 skipped |
| `tests/test_glasses_assets.py` | 4 skipped |
| `tests/test_stamp_badge.py` | 14 passed / 3 skipped |

19 个 skip，**全是同一件事**：素材不在本机。

本回路解决的就是这个：**在本地把素材生成出来**，这些用例就**真跑**。
生成完留在 `models/<slug>/assets/`（gitignore 已经挡着），下次跑回归直接用，
**不重复花钱**。

**2026-11-27 实测**：本机跑完这条链，回归从 **190 passed / 19 skipped**
变成 **209 passed / 0 skipped**——19 条 skip 全变真跑。
而这条链**自己也抓出了三处缺陷**（§3.6、§3.7），它们在素材不在的时候
一个都看不出来。

---

## 二、依赖链（真实顺序）

顺序**按代码查出来**，不是按文档抄的。四处关键点见 §三。

| # | 步骤 | 花不花钱 | 产出 |
| --- | --- | --- | --- |
| 1 | `character generate` | **联网·消耗额度** | 主形象（白底 + 透明底）、6 姿态表 |
| 2 | `character white` | 本地·合成 | 白底版（从透明底合成，像素照抄，无损） |
| 3 | `character clear-badge` | 本地 | 无标牌版（`assets.mascot_plain`） |
| 4 | `brand poses` | **联网·消耗额度** | 点赞 / 挥手透明底 |
| 5 | `character badge` | 本地 | 铭牌盖上品牌词（真实字体）——**盖全部素材** |
| 6 | `brand backgrounds` | **联网·消耗额度** | `bg_intro.png` / `bg_outro.png` |
| 7 | `brand audio` | 本地·ffmpeg | `intro_mix.wav` / `outro_mix.wav` |
| 8 | `brand render` | 本地 | 片头 / 片尾 mp4 |
| 9 | `brand fix-plates` | 本地 | 修底板里被 16:9 裁断的文字（**目前空转**，见 §3.4） |

产出全在 `models/<slug>/assets/` 下，路径与 `model.json` 里声明的一致。

**链上少了一步**：`character glasses`——理由见 §3.2。

**盖章为什么排在姿态之后**：盖章要盖**这个人的全部素材**，而姿态图是
`brand poses` 那一步才生成的——排在它前面，那一步永远盖不到姿态图。
理由见 §3.3。

## 三、四处与现有文档/直觉对不上的地方

### 3.1 `brand audio` 必须在 `brand render` 之前

`scripts/brand/render_brand.py:506` 把音轨**烧进** mp4：

```python
render(which, bg, char, out, audio if audio.exists() else None)
```

音轨在渲片时就没了，渲出来是**静音片**。而 `docs/使用教程.md` 的 Step 5
原来把 render 排在 audio 前面——照着敲会渲出静音片，还得再渲一遍。

本回路的顺序是 **audio → render**。教程要跟着改。

### 3.2 `character glasses` 不在这条链上

`generate_character.py:89` 与 `generate_poses.py` 的 prompt **已经带眼镜**
（`look_spec.glasses` 声明了就写进 prompt，没声明一个字都不提；
`aimkit/look.py` 的 `appearance_prompt` 默认含眼镜那一行）。

`add_glasses.py` 是**另一条路**：给「已经存在的旧素材」补眼镜，
批次流程是 **生成 → 目视验收 → `--promote`**，中间有人工关卡。
新链再跑它就是 readme 里警告的「眼镜叠眼镜」。

所以：**眼镜那步不进自动链**。要用它，自己跑 `aim character glasses`。

### 3.3 `character badge` 在链上，而且排在姿态之后

`generate_character.py` 与 `generate_poses.py` 生成后**自己就盖章了**，
看着多余。但它保两件事：

- **`generate` 被跳过时**（素材已经在了），品牌词照样是最新的；
- **改了 `brand.token`** 再跑一遍，章会跟着改。

**盖章是幂等的**：盖过一次之后再盖，字节完全一样（实测 sha256 相同，
`tests/test_stamp_badge.py` 的 `test_stamp_is_idempotent` 也盯着）。
所以多盖一次不会叠字。

**顺序有讲究**：盖章要盖**这个人的全部素材**——白底版、透明底版，
还有两个姿态图。姿态图是 `brand poses` 那一步才生成的，所以盖章排在
它**后面**；白底版由 `make_white` 从透明底合成而来（像素照抄，
章会保留），排在它**后面**保的是章始终是最新的一版。

**抹铭牌**（`character clear-badge`）排在盖章**之前**：它抹的是
「带铭牌那份」——章由 `character generate` 自己盖好，抹完留一份
「无标牌版」（`assets.mascot_plain`）供平台判「过度营销信息」时用。

### 3.4 `brand fix-plates` 留着，但它目前是空转

它修的是**底板 PNG**（`<slug>_intro_1080p.png`）。而在 aim 与 aiv 两条线上
**都没有任何脚本产出底板**——只有 `fix_plates.py` 在消费它。
aim 的 `render_brand.py` 是直接画帧出 mp4，没有底板那一层。

所以这一步留着（它在 CLI 里、也许哪天底板回来了），但跑起来会自己说
「找不到底板」。

### 3.5 缺旁白 → 降级出静音片；缺原型图 → 硬停

两种缺失不是一回事：

| 缺什么 | 怎么办 | 为什么 |
| --- | --- | --- |
| **原型参考图**（`assets.source`） | **硬停**，后面的都不跑 | 没它连形象都生成不出来，跑下去只是白花钱 |
| **旁白**（`voice_intro.mp3` / `voice_outro.mp3`） | **降级**：跳过 audio，渲出静音片，并说清楚缺哪样 | 沿用 `render_brand.py` 自己的规矩——「素材缺失不是错误，渲染降级」 |
| **配乐台账**（`AIV_MUSIC_LIBRARY`） | 同旁白 | 同上 |
| **头像**（`assets.avatar`） | **报告但不阻塞** | 头像没有生成路径，是使用者自己的素材 |

**缺什么就说什么，不糊过去**——这是本仓的老规矩。

### 3.6 **素材在 ≠ 素材合格**：铭牌这条硬要求

**这是 2026-11-27 第二次跑这条链时抓出来的**，而且抓到的是三处：

1. **模型有的时候不画胸口那块白色铭牌。** 实测那一批：点赞与挥手两个
   姿态**都没画**——画面上只剩胸口那枚琥珀黄图标。章盖不上去，
   而那两张图是**片头片尾的底图**：片子渲出来没有品牌词。
2. **盖不上是静默的。** `stamp_badge` 打印一句「没找到铭牌，跳过」，
   调用方**不看返回值**（`generate_poses.py` 调完就往下走，
   `render_brand.py` 也一样），于是链照样成功、片子照样渲出来，
   **没有人收到过一句提醒**。
3. **「产物齐全就跳过」只看文件在不在。** 文件在、但它胸口没有品牌词，
   链照样当这一步做过了——坏素材一路流到成片。

所以现在有了三道关：

| 关 | 位置 | 做什么 |
| --- | --- | --- |
| **产出侧** | `generate_poses.py` | 盖不上就把这张图**删掉**（留着会被当成合格素材），并**重做**（`--tries`，默认 3 次）；还不成就报错退出 |
| **判据侧** | `build_assets.py` | 「这一步做过了」= 产出齐全 **且带品牌词**（`needs_badge`）；缺品牌词就**重做这一步** |
| **消费侧** | `render_brand.py` | 渲之前盖不上章 → **不渲**，报错说清楚 |

**要么这张图带品牌词，要么它压根不存在。** 详见
[`specs/形象规范.md`](../specs/形象规范.md) §三。

### 3.7 路径只有一个出处

四个品牌片脚本各自拼 `brand_dir(slug) / "assets"`，而 `stamp_badge.py`
与三个测试文件拼的是 `brand_dir(slug)`——**少一层**。

后果不是「找不到文件」那么轻：**三个测试文件验姿态素材的用例，
永远在找一条不存在的路径、永远 skip**——等于写了但从没跑过。
而 `build_assets.py` 的步骤表用另一套基准解析产出，
**「产出齐全就跳过」从来没生效过**，每跑一次链都把耗额度的步骤
重做一遍，**白烧额度**，屏幕上什么异常都看不出来。

现在路径收口到 `aimkit/paths.py` 的 `brand_assets_dir()`，
脚本与测试都从那儿拿。

## 四、命令

```
./aim assets build              # 跑完整条链
./aim assets build --force      # 无视「已存在就跳过」，全量重做
./aim assets build --from "brand render"   # 从这一步开始往下重做
```

### 4.1 跳过规则：只省「花钱」的那几步

**生成要花钱。** 迭代时改的是渲染逻辑（`render`、`fix_plates`、混音），
不该每次都把形象重新生成一遍。所以分两类：

| 类别 | 步骤 | 行为 |
| --- | --- | --- |
| **耗额度**（联网生成） | `character generate`、`brand poses`、`brand backgrounds` | **产出齐全、非空、且带品牌词 → 跳过** |
| **本地**（快、确定） | 其余全部 | **每次都跑** |

本地步骤每次都跑，因为改的往往就是它们（渲染、底板、混音），
而且它们不花钱。

**「带品牌词」这一条是 §3.6 那道关**：文件在**不等于**素材合格。
模型有的时候不画铭牌，那种图留着会被当成合格产物——所以判据是
「齐全 **且** 带品牌词」，缺了就重做这一步。

`--force` 无视这个跳过，全量重做（含耗额度的那几步）。
`--from <步骤名>` 从指定步骤开始**重做**（这几步不再跳过已存在的），
前面的不动——改了 `fix_plates` 就只重跑它和它后面那几步。

所以 `--force` 等于 `--from "character generate"`。

步骤名就是 CLI 上的路径（`character generate`、`brand render`……），
不用另造一套名字。名字写错就**报错列出全部步骤名**，不猜。

### 4.2 前置检查

动手之前先查一遍，**缺什么先说清楚**。两级，跟 §3.3 一个口径：

**硬缺 → 直接停**（后面的跑了也是白花钱）：

| 缺什么 | 补法 |
| --- | --- |
| 内置字体没装 | `python3 scripts/install_font.py` |
| 原型参考图 `assets.source` | 放到模型声明的那个位置 |

**软缺 → 报出来，继续跑**（沿用渲染自己的降级规矩）：

| 缺什么 | 结果 |
| --- | --- |
| 头像 `assets.avatar` | 报告；它没有生成路径 |
| 配乐台账（`AIV_MUSIC_LIBRARY`） | 跳过 `brand audio`，渲出静音片 |
| 旁白 `voice_intro.mp3` / `voice_outro.mp3` | 同上 |
| 窗口 `brand_windows.json` | 同上（它**入库**，正常都在） |

真正会缺的是**台账与旁白**——它们不在本仓（台账在 aiv 那侧）。

### 4.3 怎么实现

**逐条调现有脚本，不重写任何一步的逻辑。** 子进程调，退出码原样传回。

用子进程而不是 import，理由跟 `aimkit/cli.py:19` 完全一样：
脚本在 **import 时**就把模型读进模块里，一个进程里 import 几个脚本会撞上
`sys.modules` 里缓存的旧模块——测出来的是上一个人，而那正是要抓的错。

**不碰 `doctor`。** 它写死了「只报告，不改——`--fix` 不该存在」
（`scripts/doctor.py:8`）。生成回路是另一件事，不能塞进体检。

## 五、回归那头会变成什么

素材在本地之后：

- 那 **19 个 skip 变成真跑**（实测：190 passed / 19 skipped → **209 passed / 0 skipped**）
- 素材不在 → **照旧 skip**。缺素材不是错误，测试不能因为「用户还没生成素材」就红
- 现有的 `tests/test_assets_are_tracked.py` 继续盯着：**素材一旦被误提交，测试立刻红**

新增守卫（`tests/test_assets_build.py`）：

1. **步序**：audio 必须在 render 之前（§3.1 那个坑，钉死）；盖章要在姿态之后（§3.3）
2. **链上不该有的那一步**：眼镜不在（§3.2）
3. **链跟 CLI 是同一套实现**：每一步调的脚本都得在命令表里
4. **缺东西别花钱**：原型图不在 → **一步都不跑**，退出非 0，说清楚缺什么
5. **`--from` 名字写错 → 报错列出全部步骤名**，不猜
6. **路径只有一个出处**：步骤表里的路径解析到 `models/<slug>/assets/` 底下，
   且链上的姿态产出 == 测试验的姿态素材（§3.7）
7. **没品牌词就不算做完**：产出齐了但胸口没品牌词 → 这一步不算做过，链要重做（§3.6）

外加 `tests/test_cli.py` 自动覆盖：新脚本进了命令表（漏登记 = CLI 叫不到它）。

**还有一层是这条回路自己挣来的**：素材一旦在本地，
`test_stamp_badge.py` 的「真素材上的铭牌得带着品牌词」就是**真跑**的。

- **第一次跑完**（2026-11-27 上午）当场抓到**三枚铭牌一块都没盖上**——
  旧阈值是照上一批素材量的，新一批的铭牌被渲染成暖调的白、也更大，
  `stamp_badge` 一声不吭地跳过。详见
  [`specs/形象规范.md`](../specs/形象规范.md) §三。
- **第二次跑完**（同日下午）抓到 §3.6 与 §3.7 那三处：
  **模型没画铭牌**（两个姿态都只画出图标）→ 片子会没有品牌词；
  **盖不上是静默的** → 没人收到过提醒；**路径少一层** →
  姿态素材的断言永远 skip、耗额度的步骤永远重做。

**所以「本地有素材」这件事本身就是一个守卫**：它把「素材在不在」
从「没人验」变成「每一条素材守卫都在跑」。

## 七、验收

1. `./aim assets build` 在**缺原型图**时报清楚缺什么、退出非 0、**一步都不跑**
2. 素材齐时跑完整条链，`model.json` 声明的那几件都在 `models/<slug>/assets/` 下
3. `python3 -m pytest tests/ -q` 的 **18 个 skip 变成真跑**
4. `git status` **干净**——产物一件都不入库
5. `--force` 与 `--from` 的行为符合 §4.1
6. 每一步失败时，**报错指到具体那一步**、说清楚缺什么

## 八、明确不做

- **不改 `doctor`**（§4.3）
- **素材不入库**（§一）
- **不自动 promote 眼镜 staging**（§3.2——那是人工关卡）
- **不做逐像素基线**——跨机不可比，只同机可比；本轮目标是「素材齐、测试真跑」
- **不重写各生成脚本**（§4.3）
- **不碰音色的合成**——旁白合成不在本仓（见 `docs/使用教程.md` Step 5 的「brand audio 要三样」）
